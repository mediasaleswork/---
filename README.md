# Mediasales — агент поиска клиентов

Отдельный сервис продаж. Существующий Partner Monitor сохраняет свою задачу замеров рекламных публикаций.

Агент каждые 15 минут читает публичные веб-ленты выбранных Telegram-каналов и RSS деловых СМИ. Отбирает материалы с рекламной пометкой и конкретным брендом, а также коммерческие события: открытие, запуск, расширение, ребрендинг, партнёрство, инвестиции, мероприятие или лицензирование. Обычная реклама учитывается и без слов о запуске/открытии. Анонимные объявления без определимого бренда не превращаются в выдуманную компанию. Сохраняются источник, дата, цитата и отдельная гипотеза потребности. Первое сообщение, повторное касание, сценарий звонка и ответы на возражения готовятся из шаблонов под событие. Контекст и качество кандидата нужно проверить вручную; упоминание бренда не подтверждает прямого заказчика размещения.

API нейросетей, ключи Gemini/OpenAI, платный биллинг и квоты генерации не используются. Это самостоятельный программный агент с правилами отбора. Он не выполняет свободный смысловой анализ публикаций. Сообщения клиентам не отправляет. Закрытые группы и личные сообщения не читает; LinkedIn не авторизован.

Google-книга: «Лиды», «Скрипты», «Публикации», «Источники», «Работа агента». В «Лиды» одна карточка компании: более новая публикация обновляет факт, дату и ссылку, сохраняя CRM-проверку, статус, следующий контакт и заметки. Ручные правки текста скрипта сохраняются; неизменённый автоматический скрипт обновляется под новый повод. «Публикации» содержит историю по каждой ссылке и компании, включая повторные размещения на разных площадках. Удалённая строка восстановится из базы; для отказа используйте статус «Не подходит». Сортировка допустима: связь по ID.

Новая компания или более свежая публикация поднимает карточку в «Лиды» наверх по дате публикации. Сортируются полные строки, включая ID, CRM-поля и дополнительные колонки команды. Запись по номерам строк завершается до сортировки. «Публикации» также показывает новые выходы первыми.

При рекламной публикации о рейтинге приоритет получают явно указанное юридическое лицо и полное название университета, чтобы название рейтинга или агентства не подменяло рекламируемую организацию. Подтверждённые в источниках русские/узбекские варианты названия ТАФУ и Uztelecom связываются с одной карточкой, история публикаций сохраняется.

«Дата публикации (Ташкент)» — дата и время выхода исходного поста/статьи в часовом поясе Asia/Tashkent. Для пересланных сообщений берётся время публикации в отслеживаемом канале. «Проверено UTC» отдельно показывает время проверки агентом.

## Запуск

Python 3.12+: `pip install -r requirements.txt`. Секреты задаются только в окружении:

- `GOOGLE_CREDENTIALS_JSON`: существующая Google OAuth/service-account конфигурация. Программа сохраняет её в приватный файл на постоянном томе. Ключ в чат и Git не передавать.
- `SALES_DATA_DIR`: путь постоянного тома, на Railway `/app/data`.
- `SALES_CONFIG_JSON`: JSON с `spreadsheet_id`, `channels` (публичные username), `feeds` (HTTPS RSS), при необходимости `scan_interval_minutes` (15), `timezone`, `lookback_days`, `max_leads`.

`python -m sales_agent run` — постоянная работа; `once` — ручной цикл; `status` — состояние локальной базы. Не запускайте два экземпляра на одном томе/таблице.

Мониторинг работает круглосуточно с интервалом 15 минут. Время последнего цикла сохраняется на постоянном томе и переживает перезапуск. Google-синхронизация каждые пять минут. В «Работа агента» B2 — пауза (TRUE/Да). Она останавливает плановый поиск, синхронизация продолжается; явный CLI `once` выполняется вручную.

Окно свежести 14 дней, до 10 новых компаний за цикл; оставшаяся очередь сохраняется. Публичная веб-лента Telegram содержит ограниченное число последних публикаций: это поиск по доступной ленте, а не гарантированная полная выгрузка истории канала. База, очередь и результаты остаются на постоянном томе. При сетевом сбое цикл повторяется; поиск и запись в Google разделены. Неизвестные названия без достаточно явных признаков пропускаются. При переходе с прежнего режима текущие истории один раз проверяются заново, существующие строки CRM сохраняются.

Дедупликация по нормализованному названию компании. Алиасы бренда могут потребовать ручной сверки. CRM агентства не предоставлена: колонка «CRM-проверка» должна быть заполнена до обращения. Публичная ссылка/новость не доказывает бюджет, рекламную потребность или полномочия контакта. Контактный маршрут честно помечается непроверенным, если источник не содержит подходящей ссылки.

## Проверка

`python -m unittest discover -s tests -v`. Проверяются извлечение русских/узбекских названий и событий, дословные цитаты, отказы для конкурентов и неоднозначных публикаций, отсутствие вызовов API нейросетей, повторный запуск, дедупликация, интервал мониторинга и сохранность ручных правок. Docker выполняет те же проверки перед запуском.
