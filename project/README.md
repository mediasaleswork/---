# Partner Monitor 0.4

Юзербот читает доступную рабочую группу Telegram, извлекает заявки на рекламу, получает новые публикации без вступления и сразу запускает первый скриншот нужного поста. История проверяется отдельно для восстановления пропусков. Результаты сохраняются в SQLite, Excel и, при настройке, Google Sheets.

Проект не авторизован и не запущен от вашего имени. Нужны ваши Telegram API ID/hash и локальная авторизация. Ключи и сессии в архив не включены.

## Первый снимок сразу после появления поста

В постоянном режиме `run` используются события Telegram и поддержание потока обновлений публичных каналов через `updates.getChannelDifference`. В каналы аккаунт не вступает. Для публичных каналов без подписки этот режим включается максимум для **10 одновременно наблюдаемых каналов** — ограничение из [документации Telegram об обновлениях](https://core.telegram.org/api/updates). Выбираются первые доступные активные каналы. Если аккаунт уже состоит в канале, используются его обычные события, отдельное место среди десяти не требуется.

Когда приходит подходящий пост, снимок запускается сразу, без ожидания резервного цикла истории. Сам снимок требует загрузки виджета и медиа. Для альбома сначала собираются его сообщения. Excel и Google Sheets обновляются отдельной задачей после снимка, без ожидания завершения опроса остальных каналов. Событие и история одного поста не создают два первоначальных снимка.

Настройка `realtime_channel_limit: 10` задаёт число публичных каналов без подписки в быстром режиме, от 0 до 10. Значение 0 выключает поддержание таких потоков, но сохраняет обычные события уже доступных каналов. Остальные каналы проверяются по `interval_seconds`, и для них немедленный снимок не обещается. `run --once` выполняет только один проход истории; постоянное получение событий доступно в `run`.

Сервис соблюдает `timeout` Telegram для поддержания потока и общую паузу `FloodWait` для всех режимов. Доставка зависит от соединения, сервера Telegram и доступности виджета: гарантии снимка в ту же секунду нет. После сбоя история дочитывается с отдельного курсора, поэтому новое событие не пропускает старые сообщения. На реальном аккаунте доступность быстрого режима необходимо проверить после авторизации.

## Формат заявки

Одна заявка — один канал и одно рекламное размещение:

```text
Клиент: Название клиента
Название: Название рекламируемого продукта
Язык: UZ
План публикаций: 10
Тип рекламы: пост с видео
Канал: https://t.me/partner_channel
Длительность: 24 часа
Условия: без удаления в течение срока размещения
Дата публикации: 06.11.2026
```

`Название` — рекламируемый бренд, продукт или услуга, фраза для поиска в тексте/подписи поста. Поддерживаются также `Бренд`, `Продукт`, `Услуга`, `Название рекламы`, `Реклама`. При необходимости задайте более надёжный признак:

```text
Искать: Уникальное название продукта; Название бренда
Домен: example.uz
```

Фразы в `Искать` разделяются точкой с запятой: достаточно одного совпадения. Домены проверяются по имени хоста, включая поддомены. `Текст рекламы:` может содержать несколько строк: весь текст проверяется одной нормализованной фразой. Приоритет: `Искать`/`Ключевые слова`, затем `Текст рекламы`, затем название. Домены дополняют текстовые признаки. Совпадение означает кандидата на размещение, а не доказательство оплаты.

Прямая ссылка `https://t.me/partner_channel/123` ставит именно этот пост на контроль без ключевых слов. Поддерживаются `@channel`, `t.me/channel`, `t.me/s/channel/123`, `telegram.me`, скрытые гиперссылки и раскрытый Telegram источник пересылки. Для пересылки без названия рекламы нужна прямая ссылка на исходный пост либо резервный признак в конфигурации.

### Длительность и период поиска

**`Длительность: 24 часа` — сколько реклама должна оставаться в канале после публикации.** Срок выхода указывается отдельно:

```text
Начало: 2026-11-06 10:00
Окончание: 2026-11-06 18:00
```

Также поддерживаются `Дата публикации: 06.11.2026` (весь местный день), `Период: 2026-11-06 — 2026-11-08`, `Срок публикации: 48 часов` (от сообщения группы). Часовой пояс — из конфигурации. Начало включается, окончание исключается; дата без времени на правом краю включает весь указанный день.

Если дата не указана, поиск идёт **7 дней от времени сообщения группы** (`default_window_days`), с явной отметкой в таблице. Прямая ссылка на пост обрабатывается независимо от периода поиска.

После обнаружения доступны первичный замер, точки `milestones_hours` и итоговый замер в конце длительности размещения. Пока длительность не истекла, доступность поста проверяется каждый цикл. Недоступность фиксируется как `unavailable`: удаление, потерю доступа и временный сбой нельзя надёжно различить одним запросом. Периодические проверки не доказывают непрерывную доступность между ними.

При позднем обнаружении прошлые просмотры не восстанавливаются. Если срок размещения уже истёк, прошлое не помечается подтверждённым. Итоговый замер выполняется в ближайшем цикле после срока; плановое и фактическое время сохраняются отдельно.

### Файлы и уточнение

Извлекаются текст и ссылки из **DOCX, XLSX, PDF с текстовым слоем и TXT в UTF-8**. Лимиты: 20 МиБ, PDF до 100 страниц. Для Excel используйте строки «поле — значение» в двух соседних ячейках, поля внутри ячейки или заголовки столбцов `Название`, `Канал`, `Длительность`. Несколько заявок в одном файле требуют уточнения. Поддерживаются также таблицы DOCX с отдельными ячейками для поля и значения.

Содержимое файлов — исходные данные: инструкции, макросы, формулы и команды из вложений не выполняются, внешние ресурсы документа не загружаются. Вложения удаляются после чтения.

Несколько каналов, несколько названий рекламы, неясные даты, конфликтующая длительность или отсутствие признака рекламы переводят заявку в `needs_review`. Её сканирование не начинается. Фотографии, сканы PDF и неподдерживаемые вложения требуют текстового уточнения. OCR и распознавание рекламы по изображению/аудио не подключены. Разбор детерминированный: это не универсальная языковая модель для любого свободного текста. Неизвестные типы и условия сохраняются текстом.

Уведомления в группу не отправляются. Очередь уточнения видна в отчёте и команде `review`.

## Установка и запуск на Windows

Нужен Python 3.11+; проверено на Windows / Python 3.13. Из папки проекта:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\partner-monitor.exe init
```

Получите собственные `api_id` и `api_hash` в разделе API development tools на https://my.telegram.org. Задайте их локально в том же окне PowerShell:

```powershell
$env:TELEGRAM_API_ID = 'ваш_api_id'
$env:TELEGRAM_API_HASH = 'ваш_api_hash'
.venv\Scripts\partner-monitor.exe login
.venv\Scripts\partner-monitor.exe dialogs
```

Телефон, код Telegram и пароль двухэтапной проверки вводятся в терминале. `data/telegram.session` предоставляет доступ к аккаунту: храните её в закрытом каталоге. Не запускайте две копии с одной базой/сессией. Укажите ID нужной рабочей группы в `config.yaml`:

```yaml
source_group: -1001234567890
keywords: []
domains: []
timezone: Asia/Tashkent
interval_seconds: 300
realtime_channel_limit: 10
lookback_days: 7
batch_size: 200
default_window_days: 7
milestones_hours: [24, 48, 168]
spreadsheet_id: ""
google_credentials: ""
drive_folder_id: ""
```

`keywords`/`domains` — необязательный общий резерв для заявок без собственных признаков. Бренды по умолчанию не заданы. Слова и домены из заявки заменяют соответствующий общий резерв.

```powershell
.venv\Scripts\partner-monitor.exe check-config
.venv\Scripts\partner-monitor.exe run --once
.venv\Scripts\partner-monitor.exe run
```

Сервис должен оставаться запущенным. Резервные циклы истории по умолчанию разделены 5 минутами; события обрабатываются между ними и во время чтения истории. Новое сообщение рабочей группы запускает проверку без ожидания этого интервала. При большой очереди восстановление истории занимает больше времени. `FloodWait` останавливает новые запросы из всех режимов на требуемый Telegram срок.

`lookback_days` — глубина первого чтения группы. История канала для новой заявки читается от начала её периода. `batch_size` ограничивает порцию за цикл; `not_found` появляется только после обработки всех нужных порций истории. Курсоры, заявки, посты и измерения переживают перезапуск. Новая реклама в прежнем канале получает отдельную заявку с собственными условиями. Смена владельца username даёт `identity_changed`, чужой канал не подставляется.

Изменения прочитанных сообщений группы не отслеживаются: пришлите исправление новым сообщением или уточните заявку через CLI.

Telegram MTProto требует сетевого доступа, одной доступности сайтов через HTTP-прокси недостаточно.

## Предварительный разбор и уточнение

Команды без подключения Telegram:

```powershell
.venv\Scripts\partner-monitor.exe preview --file examples\placement.txt
.venv\Scripts\partner-monitor.exe add "https://t.me/partner_channel/123"
.venv\Scripts\partner-monitor.exe import-file "C:\path\brief.docx"
.venv\Scripts\partner-monitor.exe review
.venv\Scripts\partner-monitor.exe resolve 3 --start "2026-11-06 10:00" --end "2026-11-07 10:00" --keyword "Название продукта" --hours 24
.venv\Scripts\partner-monitor.exe dismiss 4
.venv\Scripts\partner-monitor.exe status
.venv\Scripts\partner-monitor.exe export --month 2026-11 --output november.xlsx
.venv\Scripts\partner-monitor.exe demo
```

`preview` выводит JSON с полями и причиной уточнения, не меняя базу; есть вариант `preview --text "..."`. `resolve` уточняет одну заявку: выберите ID нужного канала, задайте период и при необходимости признаки/часы. Остальные неоднозначные заявки остаются на уточнении, ненужные отклоните через `dismiss`. `--keyword` и `--domain` можно повторять. Для вложения без извлечённого канала пришлите новую полную заявку или используйте `add` с текстом полей.

## Отчёты и Google Sheets

После успешного цикла создаётся `data/report.xlsx`:

- **Отчёт** — сводка по инструментам и площадкам: план, опубликовано, остаток, число недоступных постов и снимков. Ниже — таблица «Инструмент / Площадки / Публикация / Данные поста / Скриншот»: одна строка на пост, сгруппированная по инструменту и площадке. В строке находятся ссылка, дата выхода, статус, просмотры, время замера, срок размещения, плановое снятие и время снимка. Снимки находятся внутри XLSX, отдельная папка читателю не нужна.
- **Недоступные посты** — отдельный список со ссылками на последние сохранённые снимки в этой же книге. `Недоступен` не означает подтверждённое удаление.
- **Реестр публикаций** — таблица с фильтрами по инструменту, площадке, состоянию, месяцу и другим полям. Ссылка «Открыть снимок» ведёт к соответствующей строке главного листа; нажатие на инструмент в этой строке возвращает в реестр.
- **История просмотров** — все замеры, плановое/фактическое время и время снимка. Ссылка ведёт к текущему снимку поста, не выдавая его за старый.
- **Партнёры** — строка на заявку: инструмент, условия, план, язык, состояние, исходный текст и ссылки. Вложения без данных тоже видны как требующие уточнения.

В сводке «Заказано постов» — количество из заявок; «Опубликовано» — найденные уникальные посты за весь срок; «Осталось опубликовать» — разница между ними. «Постов за период» учитывает выбранный месяц, а без фильтра — все даты. «Не удалось открыть» — недоступные сейчас посты этого периода, что не доказывает удаление; «Постов со скриншотом» — количество постов с сохранённым снимком, а не количество всех снимков. У заголовков есть пояснения в примечаниях ячеек.

На главном листе нет закреплённых областей и разделяющих экран линий. В строке каждого поста показано компактное превью полного снимка до 240 × 280 пикселей без растягивания маленьких изображений. Исходное изображение остаётся внутри XLSX в полном разрешении. Границы строк и чередование фона разделяют группы инструментов и площадок. Подписи «Инструмент» и «Площадки» применены ко всем вкладкам Excel; поля ввода `Клиент`/`Заказчик` и структура базы остаются прежними.

Поля `Клиент` (или `Заказчик`), `Язык`, `План публикаций` (или `Количество публикаций`) берутся из сообщений и поддерживаемых файлов и сохраняются в базе. План относится к конкретной заявке; не повторяйте общий план договора в каждой новой заявке. Если клиент не указан, выводится «Клиент не указан»; бренд рекламы автоматически не считается именем клиента. При неполном плане общий остаток не выдумывается и остаётся пустым.

Сводка разделяет инструменты даже на одной площадке. Публикации считаются по уникальным постам. При экспорте за месяц учитывается местная дата публикации; план и остаток продолжают отражать весь срок заявки, а колонка «Постов за период» показывает выбранный месяц.

В строке поста показывается один последний успешно сохранённый снимок. Если новая попытка не удалась или файл отсутствует, сохраняется предыдущий доступный снимок с пояснением. При появлении нового успешного снимка он занимает это же место; записи прежних замеров остаются в базе и истории. Длинные примечания доступны полностью в комментарии к ячейке данных. Отдельная очередь заданий на замену через 20 часов пока не добавлена.

Даты в сводке, реестре и истории — настоящие значения дат с явным часовым поясом книги. В ячейке «Данные поста» они также показаны текстом рядом с другими сведениями. Публичные ссылки кликабельны. Изображения закреплены за строками главного листа, который формируется в порядке инструментов и площадок; для сортировки и фильтрации используйте отдельный реестр со ссылками на эти строки. Оформление использует серые заголовки, тонкие границы и розовую нумерацию сводки.

Для Google Sheets включите Google Sheets API и, для скриншотов, Google Drive API в своём Google Cloud проекте. Сохраните JSON сервисного аккаунта локально в `secrets/google.json`, дайте его `client_email` права редактора на таблицу. Заполните `spreadsheet_id` и `google_credentials: secrets/google.json`. Для загрузки изображений сервисным аккаунтом нужна папка на Shared Drive Google Workspace с правами создания файлов; укажите `drive_folder_id`.

Для личного Google Drive используйте OAuth Desktop app: настройте экран согласия и сохраните JSON клиента в `secrets/oauth-client.json`:

```powershell
.venv\Scripts\partner-monitor.exe google-login --client-secrets secrets\oauth-client.json
.venv\Scripts\partner-monitor.exe sync-google
```

Токен сохраняется в `secrets/google.json` или по уже настроенному пути. Укажите этот путь и ID папки Drive в конфигурации. Scopes: `spreadsheets`, `drive`; учтите ограничения refresh token в режиме Testing вашего Google Cloud проекта.

Каждый цикл синхронизирует управляемые вкладки **BRB_Публикации**, **BRB_История**, **BRB_Партнёры**. Их имена сохранены для совместимости с 0.1 и не задают бренд поиска. Другие вкладки не меняются. Не редактируйте управляемые вкладки вручную. Ошибка Google сохраняет локальные измерения; синхронизация повторяется в следующем цикле.

В Google Sheets — ссылки на изображения Drive, в Excel — встроенные картинки. Права файлов не делаются публичными; читателям нужен доступ к папке. Без `drive_folder_id` данные синхронизируются, снимки остаются локально. `demo-report.xlsx` содержит явно вымышленные данные.

## Доступ и настоящие скриншоты

Публичные каналы читаются через API без вступления. `JoinChannel`, `ImportChatInvite` и отправка сообщений не используются. До 10 публичных каналов без подписки поддерживают быстрые обновления; история страхует доставку и обслуживает остальные каналы.

Для закрытых `t.me/c/...` используется уже доступный аккаунту канал. У приглашения проверяется существующий доступ через `messages.checkChatInvite`; чтение разрешается только для `ChatInviteAlready`. Новое вступление и временный preview-доступ не используются. Без подтверждённого доступа статус — `private`: ссылка сама по себе не даёт историю.

Снимки публичных постов делаются через Playwright/Chromium с проверкой точного ID, автора, времени и счётчика. Длинный пост снимается полностью. Альбом — одна публикация, просмотры первого сообщения без суммирования, снимок из реальных виджетов. Видео сохраняется постером.

**Автоматические скриншоты закрытых каналов не реализованы.** При имеющемся доступе API сохраняет ссылку, дату и просмотры; снимок отмечается `unavailable`. Для него нужен отдельный авторизованный клиент, реконструкцией текста он не заменяется. Аналогично фиксируется отказ публичного виджета; неудачный публичный снимок повторяется до трёх раз в разных циклах.

Просмотры из API — число на момент запроса. Снимок делается отдельно; его открытие может повлиять на счётчик. Времена различаются в отчёте.

Документация: [история Telegram](https://core.telegram.org/method/messages.getHistory), [приглашения и доступ](https://core.telegram.org/api/invites), [Telethon](https://docs.telethon.dev/en/stable/modules/client.html).
