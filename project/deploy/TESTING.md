# Отдельный тест перед рабочим запуском

1. Скопируйте `config.test.example.yaml` вне Git. Укажите ID отдельной тестовой группы, публичный username отдельного канала, ID копии Google Sheets и папки Drive. Ни одна рабочая группа или площадка в этом файле не нужна. Условный план — три выхода.
2. Сохраните файл на постоянном томе, например `/app/data/test-config.yaml`. В Railway задайте `MONITOR_CONFIG_FILE=/app/data/test-config.yaml`; пока оставьте `MONITOR_MODE=setup`. При новом развёртывании конфигурация будет восстановлена из этого файла. Сессия Telegram остаётся `/app/data/telegram.session`, тестовая база — `/app/data/test/monitor.sqlite3`, снимки — `/app/data/test/screenshots`.
3. Подключите Google по разделу README. OAuth-клиент и полученный refresh token остаются локально и на защищённом томе, не в чате и не в Git. Папка снимков должна быть доступна этому же Google-аккаунту. Само создание копии через подключённый Drive не заменяет этот доступ.
4. Проверьте `partner-monitor --config /app/config.yaml check-config`. Когда готовы к живому тесту, запустите один проход или переключите `MONITOR_MODE=run`. Программа не отправляет сообщения и не вступает в каналы.

## Сообщения для проверки

Оператор самостоятельно пишет в тестовую группу:

```text
Новый клиент: Тестовый клиент
```

Затем отдельным сообщением:

```text
Название: Тестовая реклама 1
Искать: Проверка продукта Альфа
Канал: @your_test_channel
```

Следующее сообщение — `Превью`. Ответом на него — `ок`. До согласования в счётчике не должно появиться выхода. После согласования оператор публикует в тестовом канале пост с фразой «Проверка продукта Альфа». Ожидаются один выход, исходный замер просмотров и настоящий снимок со счётчиком публичного виджета.

Для второго выхода используйте другой материал — фото или видео. Перешлите один и тот же медиафайл в группу и канал, укажите канал и согласуйте превью. При совпадающем Telegram ID медиа отсутствие бренда в подписи не мешает поиску. Если файл загружен заново и получил другой ID, задайте явную фразу `Искать:` или пришлите ссылку на фактический пост.

Для третьего выхода используйте альбом или rich-message-карусель. Он должен считаться одним выходом, без суммирования просмотров его элементов. Повторно перешлите готовый пост и пришлите его ссылку: счётчик должен остаться прежним.

Удалите один из тестовых постов вручную. Он должен остаться в «Отработали», остаток не увеличивается, последний успешный снимок сохраняется. При полученном Telegram-обновлении статус будет подтверждённым удалением; при одном лишь отсутствии API-ответа — недоступностью.

## Перезапуск и расписание

В SQLite `measurement_jobs` проверьте точки 24/48 часов от даты публикации, а полученные замеры — на скрытом листе «История просмотров». Перезапустите сервис: исходный снимок не должен дублироваться, будущие задания должны сохраниться. Живое прохождение 24/48 часов проверяется реальным ожиданием; автоматические тесты используют управляемое время, не подменяя им реальные отчёты.

При одновременном обсуждении двух реклам короткое `ок` без ответа не должно согласовать обе. Уточнение сохраняется в `source_messages` базы; для точного согласования ответьте на нужное превью. Правки присылайте отдельным сообщением или ответом на материал. Изменение старого сообщения через редактирование пока не заменяет такое уточнение.

Google-отчёт использует отдельную отмеченную копию компактного шаблона: «Отчёт», «Недоступные посты» и три скрытых служебных листа. Содержимое этой копии автоматически заменяется; сторонние ручные листы в неё не добавляйте. Очереди остаются в базе. Данные макета не импортируются в тестовый счётчик. Скриншоты закрытых каналов, OCR и распознавание любых свободных формулировок без уточнений не заявлены.
